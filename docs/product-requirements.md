## 1. プロダクトビジョンと目的

### ビジョン

「AIエージェントが、ログインしたユーザーの権限でしか動けない」ことをリアルタイムで体感できるデモポータル。

### 目的

AI Dev Day 2026（2026年7月24日）のセッション「エンタープライズデータへ安全につなぐ Production-ready なエージェント設計」において、以下の概念を聴衆に直感的に理解させる：

- **権限の一貫性**：エージェントがユーザーのアイデンティティを引き継いでデータにアクセスする
- **OAuth identity passthrough**：Foundry が CData Connect AI MCP を介してユーザーの権限でSalesforceに接続する仕組み
- **ゼロ追加設定のガバナンス**：ユーザーが変われば見えるデータが変わる（エージェント側の設定変更不要）

## 2. ターゲットユーザーと課題・ニーズ

### デモ視聴者（セッション聴衆）

| 属性 | 内容 |
|------|------|
| 主要ターゲット | SIer・インテグレーターのアーキテクト、テクニカルリード |
| 副次ターゲット | エンドユーザー企業のAI推進担当・企画者 |
| 課題感 | AIエージェントの PoC は動いたが「誰のデータに、どこまでアクセスするか」が制御できていない |
| ニーズ | 「ガバナンスを担保したまま本番化できる」設計パターンを具体的に見たい |

### デモ操作者（登壇者：杉本）

| 属性 | 内容 |
|------|------|
| 操作シナリオ | セッション中に画面を切り替えながらライブデモを行う |
| 制約 | 45分セッション中の12分（30:00〜42:00）で完結させる必要がある |
| 技術環境 | 会場ネットワーク・モバイルホットスポット併用（安定性を考慮した設計が必要） |

## 4. 成功の定義

### デモとしての成功

- ユーザー切替（営業担当 → 営業マネージャー）で、同じ質問への返答が変わることを聴衆が確認できる
- 「Inside the Agent」パネルで、裏側で何が起きているかを説明なしでもある程度理解できる
- デモが12分以内に完結し、リハーサル通りに動作する

### 技術的な成功

- Foundry Agent Service との接続が安定して動作する
- CData Connect AI MCP 経由で Salesforce データを正常に取得できる
- OAuth identity passthrough によってユーザーごとにデータが正しく分離される

## 6. ユーザーストーリー

### 聴衆視点

- **As a** セッション参加者
- **I want to** 異なるユーザーでログインしたときにエージェントが返すデータが変わる様子を見る
- **So that** 「エージェントはユーザーの権限を超えられない」という設計の意味を直感的に理解できる

### 登壇者視点

- **As a** デモ操作者
- **I want to** ユーザーを素早く切り替えて、同じ質問を投げられる
- **So that** 聴衆に「ユーザーが変わると結果が変わる」を30秒以内に見せられる

---

## 7. 受け入れ条件

- [ ] Entra ID でログインすると、ユーザーの名前・役職がヘッダーに表示される
- [ ] チャットで「今月のパイプラインを見せて」と入力すると、そのユーザーの権限範囲のSalesforceデータが返る
- [ ] ユーザーAとユーザーB（権限が異なる）で同じ質問をすると、返るデータが異なる
- [ ] Inside the Agent パネルに、使用したトークン種別・呼び出したMCPツール・適用されたフィルタが表示される
- [ ] デモ全体が会場のネットワーク環境（不安定な場合でも）で動作する

## 8. 機能要件

### F-01：認証

- Microsoft Entra ID（MSAL.js）でユーザー認証を行う
- ログイン後、Foundry Agent Service への Entra Token を取得する（OBO フロー）
- セッション期間中はトークンを保持し、期限切れ時は自動リフレッシュする

### F-02：チャット UI

- ユーザーが自然言語でプロンプトを入力できる
- エージェントのレスポンスをストリーミングで表示する（タイプライター効果）
- デモ用のプリセットプロンプトボタンを用意する（「今月のパイプラインを見せて」など）
- **Salesforce データはチャット内の Markdown 応答として表示する**（独立したデータパネルは持たない）
  - イントロ文（件数・合計金額）をタイプライター表示 → 商談テーブルを一括表示
  - ステージはインライン HTML の色付きバッジで表現
  - 適用されたフィルタ条件（`owner = '田中 一郎'` 等）も応答内に明示

### F-03：Inside the Agent パネル

認証・認可フロー全体を時系列で可視化する。シーケンス図の①〜⑤に対応。**シーケンス図形式**（参加者ヘッダー＋ライフライン＋矢印）でリアルタイムに進行表示する。

| ステップ | 表示内容 | 状態表示 |
|---------|---------|---------|
| ① Entra ID 認証 | ログイン済みユーザー名・ID Token 取得状態 | ✅ / ⚙️ / ❌ |
| ② OBO トークン交換 | Entra Token → Foundry 用 Access Token の交換状態 | ✅ / ⚙️ / ❌ |
| ③ Foundry 内部処理 | RBAC チェック結果・Tool Approval の承認状態 | ✅ / ⚙️ / ❌ |
| ④ CData OAuth | 初回：コンセントリンク表示・承認待ち　2回目以降：Token 保管済み | ✅ / ⏳ / ❌ |
| ⑤ MCP ツール呼び出し | Tool 名・Salesforce クエリフィルタ条件（owner 等）・レスポンスタイム | ✅ / ⚙️ / ❌ |

- 各ステップは処理の進行に合わせてリアルタイムで更新する
- ④の初回コンセント時は「コンセント待ち」として聴衆に承認プロセスを見せる
- トークン種別は色分けで識別する（Entra Token：黄 / CData Token：緑 / SF Token：ピンク）

### F-04：ユーザー切替

- 事前に準備した2ユーザー（田中・山田）をヘッダーのドロップダウンで素早く切り替える
- **切り替え時はチャット履歴を保持する**（同じ質問を再送すると返るデータが変わることを対比で見せるため）
- シーケンス図の⑤フィルタ注記（`owner = '田中 一郎'` 等）はユーザー切替に連動して変化する

## 9. 非機能要件

| 項目 | 要件 |
|------|------|
| レスポンス | エージェント初回応答まで10秒以内（会場ネットワーク考慮） |
| 可用性 | デモ時間（12分）中の無停止動作 |
| セキュリティ | Entra Token・CData Token をブラウザのローカルストレージに保存しない |
| 画面サイズ | 外部モニター出力想定（1920×1080 以上） |
| ブラウザ | Chrome 最新版で動作保証 |
